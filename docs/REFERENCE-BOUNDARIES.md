# REFERENCE BOUNDARIES

## What we may learn from references

- decision cadence;
- information hierarchy;
- tension/release timing;
- autobattle readability;
- formation and targeting grammar;
- how builds become visible behavior;
- reward pacing;
- tutorial structure;
- production pipeline techniques.

## What we must make our own

- world and fiction;
- character designs and names;
- art direction;
- exact combat rules;
- UI composition and iconography;
- progression/economy;
- unit roster;
- abilities and text;
- maps and encounters;
- music/audio identity.

## Rule of thumb

Never ask “How do we reproduce that system?”
Ask “What player problem does that system solve, and what is our own solution?”
