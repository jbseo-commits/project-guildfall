# PROTOTYPE PLAN

## P0 — Decision lock
Before real implementation:
- D001 fantasy identity
- D002 control vs automation boundary

## P1 — Greybox duel
Goal: validate the emotional loop, not content.

Maximum scope:
- 3 player units
- 3 enemies
- 2–3 behavior archetypes
- 1 strategic pre-battle choice
- 1 commit action
- 5–15 second automatic fight
- deterministic replay seed
- 1 result/debrief screen

No inventory, campaign map, town, rarity system, crafting, lore codex, gacha, or meta-progression.

## P2 — Build divergence test
Create two builds that use the same raw power budget but behave visibly differently.

Pass condition:
- A blind viewer can describe the difference between Build A and Build B from the fight alone.
- The player can predict at least one consequence before pressing Commit.

## P3 — Adaptation loop
Add one post-fight decision that directly addresses something observed in battle.

Pass condition:
- The next attempt visibly changes.
- “Why did I win/lose?” is answerable without opening a spreadsheet.

## P4 — Identity slice
Only after D001 is stable:
- first real art direction;
- one signature faction/party fantasy;
- one distinctive enemy;
- one signature combat interaction;
- sound/hit-stop/VFX pass.

## Stop conditions
Do not scale content if:
- watching battle is boring;
- results feel random or unreadable;
- strategic choices only change percentages;
- the best strategy is obvious every time;
- the battle is more fun to skip than watch.
